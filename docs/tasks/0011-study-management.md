# 실제 스터디 데이터 연동과 자율 스터디 승인·선발

## Goal

스터디 예시 데이터를 DB 목록·상세로 교체하고, 자율 스터디의 부원 개설 요청 → 관리자 승인 → 참여 신청 → 대표 선발을 제공한다.

## Context

0004 기획과 0009 부원 관리의 Supabase PostgreSQL·Prisma·NestJS, 학교 Google 인증, 학기별 승인 회원·관리자 권한을 재사용한다.

## Scope

apps/web, apps/admin, apps/api, packages/contracts 및 실행 안내.

## Requirements

- 학기별 Study·StudyApplication 모델과 추가 마이그레이션. 대표는 자율 스터디 정원에 포함한다.
- 승인된 스터디만 공개하며 신청자 개인정보·개설 반려 사유는 공개 응답에서 제외한다.
- 현재 학기 승인 부원의 자율 개설·신청. 대표의 개설 수정은 재승인 대상으로 전환한다.
- 복수 신청, 대기 신청 취소, 대표·관리자의 선발·반려·참여자 탈퇴 처리.
- 모집 기간 밖 신규 신청 차단, 모집 종료 후 선발 허용. 승인 당시에도 신청자의 학기 승인 상태를 검증한다.
- 스터디별 사용자 신청 기록은 유일하게 유지한다. 취소·탈퇴 후 재신청 시 같은 기록을 갱신한다. 반려 신청은 재신청하지 않는다.
- 현재 학기 변경 후 과거 기록을 보존한다. 일반 부원의 과거 변경은 차단하고 관리자 운영 처리는 허용한다.
- 정규 스터디 관리자 등록·수정과 공개 목록·상세.
- 직렬화 트랜잭션·버전 검증·감사 로그. 동시 충돌은 기존 API 규칙에 따라 409로 반환한다.

## Constraints

정규 참여 신청·조 편성, 회차 기록, 알림, 지원금은 제외한다. 실제 초기 자료 이전은 Notion 접근 확보 후 진행하며 예시 데이터는 운영 DB에 넣지 않는다. 기존 회원·학기 데이터를 삭제하지 않는다.

## Acceptance Criteria

- [x] DB 마이그레이션과 승인·선발·재승인·취소·탈퇴·학기 전환을 검증한다.
- [x] HTTP 공개 응답 개인정보 제외와 대표·관리자 권한을 검증한다.
- [x] 웹·관리자 화면과 모바일 흐름을 확인한다.
- [x] lint, typecheck, test, build, 포맷 결과와 외부 연동 제한을 기록한다.

## Verification

2026-10-11, Node 26.8.1 / pnpm 12.3.4.

- 전체 lint, typecheck, 프로덕션 build, format:check 및 git diff --check 통과.
- 운영 DB와 분리된 임시 PostgreSQL 18에서 기존 초기 마이그레이션과 추가 스터디 마이그레이션 적용을 확인했다.
- API 테스트 18개 통과, 건너뛴 테스트 없음. 기존 회원 흐름과 새 스터디 개설 권한·반려·재제출·재승인·공개 정보 제한·신청·취소·동시 선발 정원·탈퇴·모집 종료 후 선발·버전 충돌·학기 전환을 검증했다.
- HTTP 테스트로 비로그인 공개 상세, 공개 응답의 개인정보·반려 사유 제외, 대표 외 신청자 조회 403, 관리자 조회, 인증 없는 관리 조회 401과 UUID 검증을 확인했다.
- Playwright로 분리된 테스트 API·실제 DB와 테스트 인증 응답을 사용해 개설 제출 → 관리자 승인 → 상세 참여 신청 → 대표 선발 → 내 스터디 승인 결과를 확인했다. 정규 등록과 공개 목록 노출, 검색·유형 필터·빈 결과, 상세 404, 503 오류와 재시도도 확인했다.
- 인증 모의 처리를 제거한 비로그인 웹 공개 프록시 조회가 200을 반환함을 확인했다. 실제 학교 Google OAuth 로그인은 재실행하지 않았다.
- 목록은 320/390/1024/1440px, 대표 관리와 관리자 목록은 390px에서 가로 넘침이 없음을 확인했다. 데스크톱·모바일 캡처를 시각 검토했으며 output/playwright/study-*.png에 보관한다.
- 폼 제출 버튼에 type=submit을 명시해 공통 버튼의 기본 type=button으로 제출이 실행되지 않는 문제를 수정했다. 제출 동작을 브라우저에서 다시 검증했다.
- 테스트용 브라우저·API·웹 프로세스를 종료하고 브라우저 테스트 데이터를 정리했다.
- 기존 Supabase DB의 초기 마이그레이션은 적용되어 있고 새 스터디 마이그레이션은 미적용임을 읽기 전용으로 확인했다. 운영 적용 시도는 자동 승인 검토에서 거부됐다. 운영·공유 DB에 영구 변경을 적용할 명시적 대상 승인이 필요하다는 이유이며, 우회 실행하지 않았다. 이후 아래 추가 검증에서 사용자 승인을 받아 적용을 완료했다.
- 실제 초기 운영 자료 이전은 이번 범위에서 제외했으며, 운영 DB에 테스트 스터디를 넣지 않았다.
