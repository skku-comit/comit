# 코밋 웹사이트 기획

## Goal

코밋을 대외적으로 소개하고, 부원들이 신규 가입·학기별 재등록부터 스터디 참여까지 이용할 수 있는 웹사이트를 구축한다. 이 문서는 제품의 전체 방향과 첫 버전 범위를 정리한다. 화면 디자인과 기술 설계는 후속 작업에서 구체화한다.

## Context

### 코밋의 정체성

- 성균관대학교 자연과학캠퍼스 소속 중앙 프로그래밍·AI 동아리다.
- 전공·학년·실력에 관계없이 코딩과 AI에 관심 있는 학생들이 함께 배우고 지식을 나누며 교류한다.
- 제공된 소개 자료 기준 매 학기 약 100명이 참여한다. 실시간 회원 수를 뜻하지 않는다.
- 주요 활동은 정규·자율 스터디, 에이전틱 코딩 세션, 프로젝트·해커톤, 홈커밍 데이 등이다.

- 사용자가 제공한 코밋 소개 이미지: 소속·소개·연혁·주요 활동의 근거다.

- 노션 하위 페이지 전체와 FORIF 로그인 이후 기능은 확인하지 못했다. 과거 스터디 보상 제도를 현재 정책으로 간주하지 않는다.

## Scope

### apps/web

공개 소개와 모집 안내, 학교 구글 로그인, 신규 가입·재등록, 부원 공지와 스터디 참여 공간을 담당한다.

### apps/admin

학기 설정, 회원 신청·입금 확인·승인, 스터디 모집과 조 편성, 공개 콘텐츠·공지 관리를 담당한다.

### apps/api

인증·권한, 계정과 학기별 회원 등록, 스터디와 참여 신청, 콘텐츠를 관리한다. 데이터베이스와 API 계약은 후속 기술 설계에서 정한다.

## Requirements

### 1. 정보 구조

| 메뉴             | 내용                                                         | 공개 범위                              |
| ---------------- | ------------------------------------------------------------ | -------------------------------------- |
| 코밋 소개        | 소개, 가치, 주요 활동, 연혁, 운영진 소개·문의                | 공개                                   |
| 스터디           | 정규·자율 가이드, 학기별 목록, 주제·대상·모집 상태·상세 소개 | 소개는 공개, 신청과 구성원 정보는 내부 |
| 활동             | 세션, 프로젝트·해커톤, 홈커밍·교류 행사, 활동 기록           | 공개 소개와 내부 안내 구분             |
| 소식             | 모집 공고, 공개 소식, 부원 공지                              | 게시물별 공개·부원 전용 구분           |
| 가입 안내        | 대상, 모집 기간, 절차, 회비 안내, FAQ                        | 공개                                   |
| 로그인 / 내 활동 | 등록 상태, 신청 내역, 내 스터디, 내부 공지                   | 본인 및 허용된 부원                    |

홈은 소개 메시지와 활동 사진 → 현재 모집·주요 행사 → 주요 활동 소개 → 이번 학기 스터디 → 최근 활동·소식 → 소개 요약·문의·SNS 순으로 구성한다. 모집이 없으면 모집 종료 상태와 다음 안내를 표시한다. 확인되지 않은 일정은 표시하지 않는다.

### 2. 신규 가입·재등록: 확정된 방향

- 학교 구글 계정으로 로그인한다. 사이트 계정과 학기별 동아리 등록을 별도로 관리한다.
- 신규 가입과 기존 부원 재등록 모두 사이트에서 신청한다. 기존 계정은 다음 학기에도 유지한다.
- 신규 신청자는 가입 정보를 작성하고, 재등록자는 기존 정보를 확인·수정한다.
- 학기별로 신규·재등록 모집 기간과 회비 금액, 납부 계좌를 설정한다.
- 온라인 결제 대신 계좌 이체를 안내하고 운영진이 입금을 수동 확인한다.
- 운영진이 회비 납부를 확인한 뒤 승인해야 해당 학기의 활동 회원으로 확정된다.
- 신청자는 본인의 신청 내용, 입금 확인 여부, 승인 상태와 보완 요청을 확인한다.
- 운영진은 학기·신규/재등록·처리 상태로 신청을 조회하고 입금 확인, 승인, 보완 요청을 처리한다.

### 3. 회원 상태와 권한: 설계 초안

- 계정에는 개인 정보와 가입 이력을, 학기 등록에는 신청 유형·입금 확인·승인 상태를 둔다.
- 신청 상태는 승인 대기·보완 요청·승인 완료·반려로 구분하고, 입금 확인 여부는 별도로 표시한다.
- 미승인 사용자는 공개 정보와 본인의 가입 관련 화면을 이용한다. 승인된 활동 회원은 해당 학기의 스터디 신청과 내부 기능을 이용한다.
- 스터디 대표는 소속 스터디 관리 권한을 가진다. 회차별 진행 담당자와 구분한다.
- 관리자 기능은 서버에서도 권한을 검증한다. 메뉴 숨김만으로 접근을 제한하지 않는다.
- 학기가 바뀌어도 과거 회원·스터디 기록은 보존한다. 과거 기록의 부원 열람 범위는 정책 확정이 필요하다.

### 4. 스터디: 운영 방식 반영

- 정규 스터디와 자율 스터디를 구분하고 학기별로 관리한다.
- 정규 스터디는 운영진이 모집 주제·커리큘럼을 등록하고 신청자를 조로 편성할 수 있도록 한다.
- 자율 스터디는 부원의 개설 제안과 참여 모집을 지원한다. 제안 승인 및 참여자 선발 방식은 추가 확인한다.
- 부원은 상세 내용을 확인해 신청하고 내 활동에서 신청 결과와 소속 조를 확인한다.
- 운영진은 추가 모집과 구성원·대표 변경을 처리할 수 있도록 한다.
- 회차별 담당자·날짜·장소·학습 내용·자료 링크를 기록하는 공간은 후속 단계에 포함한다.
- 점수, 순위, 지원금 자동 산정, 수료증은 현재 정책 확인 전 구현 범위에 포함하지 않는다.

### 5. 첫 버전과 확장 순서: 제안

| 단계      | 제공할 기능                                                                                                                                                 |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 첫 버전   | 공개 소개·연혁·활동·모집 안내, 학교 로그인, 신규 가입·재등록, 회비 안내와 수동 확인·승인, 부원 공지, 정규·자율 스터디 목록·신청·조 편성, 필요한 관리자 화면 |
| 다음 단계 | 스터디 회차별 담당자·자료·활동 기록, 세션·행사 신청과 내 일정, 공개 활동 아카이브 확장                                                                      |
| 이후 검토 | 친바 미션, 프로젝트 팀 모집, 지원금·회계 관리, 운영진 업무 관리, 졸업생 교류 기능                                                                           |

첫 버전의 활동 소개와 소식은 관리자에서 게시·수정한다. 행사 신청 등 아직 사이트가 지원하지 않는 절차는 안내문과 기존 도구 링크로 연결한다. 노션 자동 동기화는 첫 버전에 포함하지 않는다.

## Constraints

- 현재 단계는 기획 문서 작성이며 앱 구현이나 기존 운영 데이터 이전은 수행하지 않는다.
- 신규 가입·재등록의 사이트 처리, 학교 구글 로그인, 입금 수동 확인 후 운영진 승인은 사용자와 합의한 사항이다. 나머지 초안과 단계 구분은 제안이다.
- 첫 개발 작업 전에 학교 계정 허용 도메인, 신청 필수 항목·동의 내용, 재등록 판별 기준, 모집 종료 후 처리와 환불 절차를 확정한다.
- 졸업생·휴학생 자격, 미재등록자의 접근 범위, 학기 전환 시 권한, 관리자별 권한 범위를 확정한다.
- 스터디 중복 신청·정원·선발·취소 규칙, 자율 스터디 개설 승인 여부를 확인한다.
- 최종 공개 문구·사진·연혁과 회비 금액·계좌는 운영진 확인 자료를 사용한다.
- 구현 작업은 인증·회원 등록 → 스터디 → 콘텐츠 등 기능 단위 task로 나누고, 각 task에서 기술 설계와 검증 항목을 확정한다.

## Acceptance Criteria

### 이번 기획 문서

- [x] 공개 영역·부원 영역·관리자 영역의 역할을 구분했다.
- [x] 신규 가입·재등록·회비 확인·승인 흐름을 정리했다.
- [x] 정규·자율 스터디와 회차별 담당자 구분을 반영했다.
- [x] 첫 버전 제안과 확장 후보를 구분했다.
- [x] 확인한 자료의 범위와 미확정 정책을 명시했다.

### 구현 시 검증할 핵심 시나리오

- 신규 신청 → 회비 안내 → 운영진 입금 확인 → 승인 → 스터디 신청이 이어진다.
- 기존 계정으로 다음 학기 재등록이 가능하고 과거 등록 기록이 유지된다.
- 동일 계정의 같은 학기 중복 신청을 방지한다.
- 입금 미확인 상태에서 승인할 수 없고 보완 요청 후 재제출할 수 있다.
- 미승인 사용자와 일반 부원은 관리자 기능이나 타인의 신청 정보를 조회·수정할 수 없다.
- 모집 종료·스터디 정원 도달·학기 전환은 확정된 정책에 맞게 처리된다.
- 비로그인 방문자가 모바일에서도 소개·모집 안내·스터디 정보를 확인할 수 있다.
