# 2026년 2학기 정규 스터디 등록

## Goal

사용자가 제공한 실제 정규 스터디 5개를 새 현재 학기 ‘2026년 2학기’에 등록한다.

## Context

0011 스터디 관리와 0012 디자인. 사용자 사진의 제목과 확인된 9월 1~4일 모집 기간, 정원 제한 없이 운영진이 팀을 구성하는 규칙을 반영한다.

## Scope

학기·스터디 실제 데이터 등록 스크립트와 정원 제한 없음의 API·관리자 입력·공개 표시.

## Requirements

- 정규 스터디에서만 capacity 0을 정원 제한 없음으로 사용한다. 자율 스터디는 1 이상을 유지한다.
- 한국 시간 2026-09-01 00:00부터 2026-09-04 23:59:59.999까지 모집 기간을 저장한다.
- 미제공 운영 정보는 추후 안내로 표시한다. 실제 신청·팀 편성 기능은 추가하지 않는다.
- 기존 학기·회원 기록을 보존하고 새 학기를 현재로 지정한다. 부원 모집 설정은 기존 학기에서 복사하되 모집을 열지 않는다.
- 단일 직렬화 트랜잭션, 감사 기록과 중복 등록 방지를 제공한다.

## Constraints

운영진·대표·회원·신청 기록을 만들어 내거나 기존 데이터를 삭제하지 않는다. 데이터 스크립트는 자동 마이그레이션에 포함하지 않는다.

## Acceptance Criteria

- [x] 새 현재 학기와 정규 스터디 5개를 DB·공개 API에서 확인한다.
- [x] 정원 제한 없음 표시와 자율 정원 제약을 확인한다.
- [x] 관련 검사 결과를 기록한다.

## Verification

- 기존 Supabase DB에 단일 트랜잭션으로 새 학기와 승인된 정규 스터디 5개를 등록하고 감사 기록을 남겼다. 현재 학기 ID는 `aec2b253-db19-4f3c-986b-35f45ac46ebf`다.
- 실제 공개 API 목록 total 5, 한국 시간 9월 1~4일의 UTC 저장 값과 capacity 0을 확인했다. 브라우저 목록에서 정원 제한 없음 표시 5개를 확인하고 C 기초 상세에서 모집 기간·운영진 팀 구성 안내를 확인했다.
- 전체 typecheck·lint·format 검사와 diff 검사 통과. API 테스트 4개 통과(정규 무제한 허용·자율 정원 0 거부·음수 거부 포함), 격리 테스트 DB를 지정하지 않아 DB 통합 테스트 3개는 건너뛰었다. 운영 DB에 테스트를 실행하지 않았다.
- 전체 API·웹·관리자 프로덕션 build 통과. 로컬 포트 바인딩이 필요한 테스트와 Next.js 빌드는 샌드박스 제한 실패 후 허용된 권한으로 다시 실행했다.
