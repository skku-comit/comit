# 스터디 화면 디자인 정리

## Goal

사용자 스터디 화면을 기존 코밋 디자인 시스템과 통일하고 각 데이터 로딩에 레이아웃에 맞는 스켈레톤을 제공한다.

## Context

0011 스터디 기능과 0005 디자인 시스템. 실제 API·권한·신청 규칙을 유지한다.

## Scope

apps/web의 스터디 목록·상세·개설·내 스터디·대표 관리와 packages/ui의 필요한 shadcn 컴포넌트.

## Requirements

- 기존 Card·Badge·Button·Input·Textarea·Field·Alert·EmptyState·Skeleton과 토큰을 재사용한다.
- 부족한 페이지네이션·구분선은 공식 shadcn 레지스트리에서 UI 패키지에 추가하고 exports·Storybook 예제를 제공한다.
- 목록은 기존 공개 활동 화면의 여백·타이포·카드 밀도를 따르고 행동·모집 상태를 구분한다.
- 상세와 폼은 정보·신청·운영 영역을 나누고 모바일·다크 모드·키보드 접근성을 유지한다.
- 목록 데이터, 상세 서버 조회, 본인 신청 상태, 내 스터디와 대표 관리 조회에 적절한 스켈레톤을 제공한다. 제출 중에는 버튼 로딩을 제공한다.

## Constraints

DB·백엔드·모집 정책과 관리자 화면은 변경하지 않는다. 운영 데이터에 예시 데이터를 넣지 않는다.

## Acceptance Criteria

- [x] 사용자 스터디 화면이 같은 디자인 토큰·공통 컴포넌트를 사용한다.
- [x] 로딩·빈 결과·오류·신청 상태를 확인한다.
- [x] 데스크톱·모바일·다크 화면 및 폼·필터·신청·운영 동작을 검증한다.
- [x] 관련 lint·typecheck·build·포맷·Storybook 검증 결과를 기록한다.

## Verification

전체 목록의 유형 구분 보강: 정규는 초록색·책 아이콘, 자율은 파란색·모임 아이콘을 사용한다. 명시적인 유형 배지를 함께 제공해 색상에 의존하지 않고 구분할 수 있게 했다. 기존 성공·정보 디자인 토큰을 사용하며 모집 상태 배지는 유지한다. 사용자 피드백에 따라 카드 상단 색상 테두리는 제거했다.

- `pnpm typecheck`, `pnpm lint`, `pnpm format:check`, `git diff --check` 통과.
- `pnpm --filter @comit/web build`, `pnpm --filter @comit/ui build-storybook` 통과. Storybook의 기존 번들 크기·의존성 경고는 남아 있다.
- 공식 shadcn CLI로 Pagination·Separator를 추가했고 기존 Button은 유지했다. 각 컴포넌트의 export와 Storybook 예제를 추가했다.
- Playwright로 1280px 데스크톱과 390px 모바일, 실제 테마 설정을 통한 다크 모드 배치를 확인했다. 모바일 개설 폼에 가로 넘침이 없으며 상세·내 스터디·대표 관리도 확인했다.
- 운영 DB와 분리된 임시 API에서 페이지 이동, 검색 빈 결과, 목록 스켈레톤, 오류 재시도, 신청 취소·재신청·대표 승인, 수정·재승인 요청과 개설 제출을 확인했다. 학교 로그인·관리자 승인 전체 흐름은 이번 디자인 검증에서 다시 실행하지 않았다.
- 개발 웹 서버를 최신 코드로 재시작하고 `/studies` HTTP 200을 확인했다. 운영 DB에 예시 데이터는 추가하지 않았다.
