# 커밋 컨벤션

이 저장소는 [Conventional Commits 1.0.0](https://www.conventionalcommits.org/en/v1.0.0/)을 기반으로 아래 규칙을 따른다.

## 메시지 형식

```text
type(scope): 한글 설명

선택 본문

선택 footer
```

- type과 scope는 영문 소문자로 작성한다. scope는 생략할 수 있다.
- 제목의 설명과 본문은 한글로 작성한다. 기술명과 코드 식별자는 원문을 허용한다.
- 제목은 type과 scope를 포함해 72자 이하로 작성하며, 끝에 마침표를 붙이지 않고 이모지를 사용하지 않는다.
- `추가`, `수정`, `제거`처럼 변경을 구체적으로 표현한다. `작업`, `수정 사항`처럼 내용이 드러나지 않는 설명은 피한다.
- 본문은 변경 이유나 제약 설명이 필요할 때 작성한다. 제목, 본문, footer 사이에는 빈 줄을 둔다.
- 관련 작업 문서가 있으면 footer에 `Task: 0003`처럼 문서 번호를 기록한다. 이는 GitHub 이슈 번호가 아닌 `docs/tasks/`의 작업 문서 번호다.

## type

| type       | 사용 기준                                         |
| ---------- | ------------------------------------------------- |
| `feat`     | 사용자 또는 소비자가 사용할 수 있는 새 기능 추가  |
| `fix`      | 잘못된 동작이나 버그 수정                         |
| `refactor` | 기능 추가나 버그 수정 없이 내부 구조 개선         |
| `perf`     | 성능 개선                                         |
| `docs`     | 문서 추가 또는 수정                               |
| `test`     | 테스트만 추가하거나 수정                          |
| `style`    | 공백, 들여쓰기 등 동작에 영향 없는 코드 포맷 변경 |
| `build`    | 의존성, 빌드 도구 또는 빌드 설정 변경             |
| `ci`       | CI 워크플로와 자동화 설정 변경                    |
| `chore`    | 위 분류에 해당하지 않는 저장소 유지보수           |
| `revert`   | 이전 커밋 되돌리기                                |

화면 디자인 변경에는 `style`을 사용하지 않는다. 변경 목적에 따라 `feat` 또는 `fix` 등을 사용한다. 기능 구현에 포함된 테스트와 문서는 해당 기능의 type을 따른다. `revert`의 본문에는 되돌리는 커밋 해시와 이유를 기록한다.

## scope

scope는 변경 대상 앱 또는 패키지의 디렉터리 이름을 사용한다.

- 앱: `web`, `admin`, `api`
- 공통 패키지: `ui`, `eslint-config`, `typescript-config`
- 새 앱이나 패키지가 추가되면 해당 디렉터리 이름을 사용한다.
- 여러 영역에 걸친 하나의 변경이나 저장소 전체 변경은 scope를 생략한다. 필요한 경우 본문에 관련 영역을 설명한다.

## 커밋 단위

독립적으로 설명하고 되돌릴 수 있는 변경을 하나의 커밋으로 묶는다. 해당 변경에 필요한 테스트와 문서는 함께 포함한다. 서로 무관한 기능, 버그 수정, 포맷 변경은 분리한다. 하나의 기능이 여러 앱이나 패키지에 걸친다는 이유만으로 커밋을 나누지는 않는다.

## 호환성을 깨는 변경

기존 API나 사용 방식과 호환되지 않는 변경은 type 또는 scope 뒤에 `!`를 붙이고, `BREAKING CHANGE:` footer도 함께 작성한다. footer에는 영향과 사용자가 해야 할 대응을 한글로 설명한다. `BREAKING CHANGE`와 `Task` 같은 footer 토큰은 정해진 표기를 유지한다.

```text
feat(api)!: 목록 응답을 커서 기반 페이지네이션으로 변경

BREAKING CHANGE: 목록 응답의 page 필드를 제거한다. 클라이언트는
  다음 페이지 요청에 nextCursor를 사용해야 한다.
Task: 0003
```

## 예시

```text
feat(web): 모집 신청 폼 추가
fix(api): 중복 신청 차단
refactor(ui): 버튼 변형 처리 단순화
build: pnpm 버전 업데이트
docs: 커밋 컨벤션 정의
```

본문과 작업 문서 연결이 필요한 경우:

```text
fix(api): 중복 신청 차단

동일한 회원이 같은 모집에 여러 번 신청하지 못하도록 검증한다.

Task: 0003
```

예시의 작업 번호는 형식 설명용이며, 실제 커밋에서는 관련 작업 문서의 번호로 바꾼다.
