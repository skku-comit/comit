# 스터디 운영 실행 안내

기존 [부원 관리 설정](user-management-setup.md)의 DB·Supabase·Google 인증·관리자 이메일을 재사용한다. 추가 환경 변수는 없다.

## DB 적용과 실행

환경 파일의 DB가 올바른 대상인지 확인하고 추가 마이그레이션을 적용한다. 이번 마이그레이션은 스터디 테이블만 추가하며 기존 회원 데이터를 변경하지 않는다.

```sh
pnpm --filter @comit/api db:deploy
pnpm --filter @comit/api db:generate
pnpm dev
```

빌드된 API를 사용한다면 `pnpm --filter @comit/api build` 후 API를 재시작한다. 이전 API 프로세스는 빌드만으로 갱신되지 않는다.

## 운영 절차

1. 관리자 부원 관리 화면에서 학기를 생성하고 현재 운영 학기를 지정한다. 개설자·신청자는 해당 학기 가입 승인과 계정 연결을 완료한다.
2. 관리자 `/studies`에서 학기 필터를 선택한 뒤 정규 스터디를 등록한다. 정규 스터디는 저장 즉시 공개되며 사이트에서는 참여 신청을 받지 않는다.
3. 부원은 웹 `/studies/new`에서 자율 스터디를 제안한다. 모집 기간은 한국 시간으로 입력하고 정원에는 스터디장를 포함한다.
4. 관리자 `/studies`에서 승인 대기 자율 스터디의 내용을 확인해 승인하거나 사유를 적어 반려한다.
5. 승인된 자율 스터디는 공개 상세 `/studies/:id`에서 모집 기간 안에 참여 동기를 받아 신청을 접수한다.
6. 스터디장는 `/studies/mine` → 스터디장 관리 화면에서 신청자의 이름·학번·학과·참여 동기를 확인해 선발하거나 사유를 적어 반려한다. 관리자도 같은 처리를 할 수 있다.
7. 대기 신청자는 내 스터디에서 취소할 수 있다. 승인 후 탈퇴는 스터디장·관리자가 처리한다. 취소·탈퇴 후 모집 기간 안에 재신청할 수 있으며 반려 후 재신청은 지원하지 않는다.
8. 스터디장가 개설 내용을 수정하면 재승인 대기로 바뀌며 공개 목록과 신규 신청에서 제외된다. 기존 참여·신청은 보존하고 관리자 승인 후 다시 공개한다. 관리자 수정·저장은 승인 상태로 공개된다.

여러 스터디 신청을 허용한다. 대기 신청 수는 정원에 포함하지 않으며 참여 승인 때 정원을 검증한다. 접수된 신청은 모집 종료 후에도 선발할 수 있다. 학기 전환 후 본인·스터디장는 과거 기록을 조회하고 관리자는 운영 처리를 할 수 있다.

2026년 2학기 정규 스터디는 사용자 제공 자료에 따라 C 기초, Python 기초, AI 기초, 데이터분석과AI기초(DS), 프로그래밍기초와실습(DS)를 등록했다. 모집 기간은 한국 시간 2026년 9월 1~4일이다. 정규 스터디 정원 0은 제한 없음을 뜻하며 운영진이 신청 인원에 따라 팀을 구성한다. 세부 일정·장소·대상은 추후 안내한다. 기존 Notion 자료 전체 이전은 별도 작업이다.

실제 데이터 등록 스크립트는 `apps/api`에서 `node scripts/register-2026-2-studies.cjs`로 명시적으로 실행한다. 새 학기는 현재 학기로 지정하며 기존 부원 모집 설정을 복사하되 모집은 닫아 둔다. 학기별 승인 부원은 새 학기에서 별도로 관리하며 이전 학기의 회원·신청 기록은 보존한다. 같은 학기·유형·제목의 스터디는 중복 등록하지 않는다.

## API와 계약

의료인공지능 자율 스터디는 신청 마감된 기존 운영 자료로 등록했다. `isLegacy`인 자료는 신규 신청을 항상 차단하며 미확인 과거 모집 날짜를 화면에 표시하지 않는다. 스터디장 계정과 기존 참여 이력은 추후 별도로 연결한다. 명시적 등록 스크립트는 `apps/api`에서 `node scripts/register-medical-ai-study.cjs`로 실행하며 같은 학기·제목은 중복 생성하지 않는다.

공개 조회는 인증 없이 사용할 수 있다. 나머지는 기존 Supabase Bearer 토큰·서버 권한 검증을 사용한다.

| 경로                                                    | 용도                                |
| ------------------------------------------------------- | ----------------------------------- |
| `GET /studies`, `GET /studies/:id`                      | 승인된 공개 목록·상세               |
| `GET /studies/me`                                       | 본인 개설·참여 신청 이력            |
| `POST /studies`, `PATCH /studies/:id`                   | 자율 개설·수정·재제출               |
| `GET /studies/:id/manage`                               | 스터디장·관리자 상세 및 신청자 조회 |
| `POST /studies/:id/applications`                        | 참여 동기 제출                      |
| `POST /studies/:id/applications/:applicationId/actions` | APPROVE·REJECT·CANCEL·WITHDRAW      |
| `GET /studies/admin`                                    | 관리자 학기·유형·상태 필터 목록     |
| `POST /studies/admin`, `PATCH /studies/admin/:id`       | 관리자 등록·운영 수정               |
| `POST /studies/:id/review`                              | 자율 개설 APPROVE·REJECT            |

타입은 `@comit/contracts`에 정의한다. 목록은 `page`, `semesterId`, `type`, `q`를 지원하고 관리자 목록은 `status`도 지원한다. 공개 기본 목록은 현재 학기이며 학기를 지정하면 승인된 과거 목록도 조회할 수 있다. 수정·상태 처리는 응답의 `version`을 제출한다. 반려는 `reason`이 필수다. 중복·정원·동시 충돌은 409이며 새로고침 후 최신 상태를 확인한다.

## 테스트

운영과 분리된 빈 DB에서 마이그레이션을 적용한다. 통합 테스트는 현재 학기를 전환하므로 운영 DB를 지정하지 않는다.

```sh
DATABASE_URL="$TEST_DATABASE_URL" DIRECT_DATABASE_URL="$TEST_DATABASE_URL" pnpm --filter @comit/api db:deploy
pnpm --filter @comit/api test
```

`TEST_DATABASE_URL`이 없으면 HTTP DB·통합 테스트는 건너뛴다. 파일 간 학기 전환 충돌을 막기 위해 API 테스트 파일은 순차 실행하며 정원 경쟁은 테스트 안에서 동시 실행한다.
